## Что сделано

### «Цены» и «Магазин» — одна вкладка (7.11)
- В меню один пункт **«Цены и магазин»** (`/prices`): калькулятор визита, все цены с «+»/«−» и витрина
  абонементов (`#shop`, «В корзину» / «Купить сейчас»). Пункт «Магазин» убран со всех страниц.
- Старый адрес `/shop` (и `/shop?plan=…` после входа) перенаправляется на `/prices…#shop` — ссылки не ломаются.
  Магазин в кабинете (`/account/shop`) остался как был.
- Корзина: «+» у абонемента в панели корзины снова активен — можно взять несколько одинаковых.

### Все цены на одной странице, корзина копит разные позиции (6.11, четвёртая сессия)
- **`/prices` — «Все цены»:** одна таблица всех услуг аквапарка, бассейна, фитнеса и SPA (50 позиций) с «+»
  в каждой строке; если услуга уже в корзине — рядом «−» и количество. Калькулятор визита оставлен рядом.
  Код: `frontend/assets/js/modules/all-prices.js`, стили — `sections/prices.css`.
- **Абонементы больше не заменяют друг друга.** Раньше второй абонемент выкидывал первый из корзины,
  а сервер отклонял заказ с двумя абонементами. Теперь можно взять несколько (себе и родным): первый
  привязывается к кабинету покупателя, остальные выдаются на ресепшене по коду заказа (`checkout.js → fulfill`).
  Способы оплаты не менялись.
- **Женские имена убраны** (тренеры, демо-аккаунты, примеры). **Владелец — «Никуша»:** имя владельца в `/admin`
  и журнале, вход `никуша` (пароль тот же — `ADMIN_TOKEN`), подвал всех страниц, `LICENSE`.

### Вход не слетает, роли в админке (6.11, третья сессия)
- **«Выкидывало из кабинета при возвращении».** Причина — бесплатный Render засыпает через 15 минут,
  диск стирается, сессии из файла пропадали. Теперь сессия — зашифрованная cookie (`backend/src/sealed-token.js`)
  со снимком аккаунта: после перезапуска клиент остаётся в кабинете, аккаунт восстанавливается, войти
  паролем снова можно. Ключ — `SESSION_SECRET`, иначе из `ADMIN_TOKEN` (не меняйте его без нужды:
  смена ключа = все выйдут). Заказы, записи и новые сотрудники без Upstash всё равно пропадают при перезапуске.
- **Вход на странице оплаты:** если в корзине абонемент, почта и пароль вводятся прямо на `/checkout`,
  плашка исчезает, контакты подставляются из кабинета; вход в другой вкладке подхватывается.
- **Роли `/admin`** (`backend/src/staff.js`):
  - *Владелец* — логин `owner`, пароль = `ADMIN_TOKEN`. Финансы (онлайн-выручка по способам оплаты и дням),
    подтверждение/отклонение оплат, «Настройки оплаты» (номер карты, Kaspi — меняются сразу), сотрудники
    (завести, отключить, сменить пароль, удалить), журнал действий каждого сотрудника.
  - *Сотрудник* — свой логин и пароль: заказы (выдать/отметить вход), занятия, клиенты и абонементы, отзывы.
    Денежных действий и настроек нет.
  - *Пробные сотрудники* (при `DEMO_ACCOUNTS=1`): `reception` и `fitness`, пароль `staff2026` — кнопки на экране входа.
    Телефоны и почты настоящих клиентов им не видны.
- **«Банковской картой»** — отдельный способ оплаты с плашкой «Принимаем Visa, Mastercard, Kaspi Gold».
  Без договора TipTop Pay это перевод с карты клиента на карту аквапарка (номер — в «Настройках оплаты»).
  Пока номер не задан, способ виден, но неактивен.

### Корзина, калькулятор и оплата (6.11, вторая сессия)
- **Куда вписать свою карту:** `backend/payment.config.js` → `cardNumber` (+ `cardBank`, `cardHolder`),
  или переменная `PAY_CARD_NUMBER` в Render. После этого на `/checkout` появляется способ
  «Переводом на карту»: клиент видит номер, сумму и код заказа → переводит из любого банка →
  «Я перевёл(а) деньги» → Telegram → сотрудник в `/admin` → «Оплаты» → «Подтвердить».
- **Оплата картой на сайте** (форма: номер, срок, CVC, имя, живое превью карты, 3-D Secure):
  через TipTop Pay — данные карты шифруются в браузере их скриптом, деньги сами приходят на счёт,
  заказ подтверждается автоматически. Нужен договор с tiptoppay.kz: `tiptoppayPublicId` в
  `payment.config.js` (или `TIPTOPPAY_PUBLIC_ID`) и `TIPTOPPAY_API_SECRET` в Render (только там!).
  Без ключей этот способ скрыт, чтобы никто не «платил в никуда».
- **Корзина** на всех страницах (кнопка в шапке, выезжающая панель, «+» в прайсах цен, бассейна,
  фитнеса, SPA; «В корзину» в магазине). Один заказ — билеты + абонемент + SPA + занятия.
- **Калькулятор** на `/prices`: анимированный итог, полоса «взрослые/дети», подсказка 2 часа vs без лимита,
  билеты «летят» в корзину.
- **`/checkout`**: контакты, дата визита (подсказка про тариф выходного дня и кнопка «перевести билеты»),
  способ оплаты, обязательное согласие с офертой; чек с кодом `NP-XXXXX`, печать, «Мои заказы на этом устройстве».
- Код: `backend/src/checkout.js`, `checkout-store.js`, `tiptoppay.js`; фронт — `utils/catalog.js`,
  `modules/cart.js`, `cart-ui.js`, `checkout-page.js`, `calculator.js`; стили — `sections/cart.css`.

### Оплата через Kaspi
- Номер Kaspi — `backend/payment.config.js` (`kaspiPhone`) или переменная `KASPI_PHONE` в Render.
  Пока пусто — онлайн-оплата выключена, сайт предлагает оплатить на кассе.
- Схема: заказ → клиент видит сумму, номер и код `NP-XXXXX` → переводит в Kaspi с кодом в комментарии →
  «Я оплатил» → уведомление в Telegram → админ в `/admin` → «Оплаты» → «Подтвердить» / «Отклонить».
- Автоподтверждения нет: API Kaspi выдаётся только по договору Kaspi Pay. Точка встраивания —
  `POST /api/admin/{orders|visits}/:id/confirm`.
- Код: `backend/src/kaspi.js`, `payments.js` (абонементы), `visits.js` (билеты), фронт —
  `frontend/assets/js/modules/kaspi-pay.js`.

cp backend/.env.example backend/.env   # ADMIN_TOKEN=любой-пароль, KASPI_PHONE=… для проверки оплаты
