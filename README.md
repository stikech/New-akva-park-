# Аквапарк «Нептун» — сайт

Сайт крытого аквапарка «Нептун» (Петропавловск, ул. Юрия Медведева, 41).

**Рабочая версия:** https://neptun-aquapark.onrender.com · админка: https://neptun-aquapark.onrender.com/admin
Фронтенд без сборки (HTML + CSS + ES-модули) и бэкенд на Node.js 22 — оба **без внешних зависимостей**:
`npm install` не нужен, поставить надо только Node.js ≥ 22.

Бэкенд — один процесс: отдаёт сайт, API (`/api/site`, `/api/feedback`, кабинет, магазин, расписание)
и страницу администратора `/admin` (отзывы, клиенты и абонементы; списки заказов и записей —
через API `/api/admin/orders` и `/api/admin/bookings`).

**Личный кабинет** — `/account`: регистрация и вход по почте и паролю, дашборд с вкладками
«Обзор» (сводка и показатели), «Мой профиль» (просмотр и редактирование), «Абонемент» (остаток, срок,
история посещений), **«Магазин»** (покупка и продление абонементов картой, история заказов с чеками),
**«Расписание»** (афиша на 14 дней, запись на занятия), «Настройки» (язык сайта, смена пароля,
выход на других устройствах, удаление аккаунта).
На компьютере и ноутбуке — боковое меню, на телефоне и планшете — нижняя панель вкладок.

**Дизайн.** База — минималистичная светлая тема (белая страница, разделение линиями вместо теней).
Кнопка в шапке переключает тёмную: выбор сохраняется в `localStorage`, `theme-boot.js` применяет его
до первой отрисовки (без «вспышки тёмного»), а пока пользователь не выбирал — тема следует системной.
Секции появляются при скролле (`modules/reveal.js`, IntersectionObserver — если JS не дошёл, контент
уже виден), волновая лента и hero анимируются при загрузке; всё движение уважает `prefers-reduced-motion`.

Абонемент также может оформить администратор в `/admin` → «Клиенты и абонементы».

**Магазин и оплата.** Тарифы берутся из сайта (`site-data.js`) — цены существуют только на сервере,
UI не может прислать свою. Оплата — эмулятор платёжного шлюза (сценарии как у Kaspi Pay / bePaid,
внешних зависимостей нет): любая карта, валидная по алгоритму Луна, проходит; `…0002` отклоняется
банком, `…9995` — «недостаточно средств». Заказы идемпотентны (`Idempotency-Key`), переход
`pending → paid` атомарный (двойной клик не спишет деньги дважды), чеки подписаны HMAC-SHA256
(`PAYMENT_SECRET`), данные карт не хранятся — только последние 4 цифры. Хранилище — JSON-файлы без
SQL, запросы строятся по фиксированным полям, уникальный `planId` ищется в каталоге — SQL-инъекциям
поддаваться нечему. Подробнее — [`docs/api-contract.md`](docs/api-contract.md).

**Демо-аккаунты** (`DEMO_ACCOUNTS=1`, включено в `render.yaml`), пароль у всех `neptun2026`:
`demo@neptun.kz` — абонемент в бассейн, `gold@neptun.kz` — «Золотая» карта, `new@neptun.kz` — без абонемента.
На экране входа они доступны кнопками. Пересоздаются при каждом запуске сервера, поэтому не пропадают
на бесплатном Render; смена пароля и удаление для них отключены.

> ⚠️ Аккаунты хранятся в `DATA_DIR/accounts.json`. На бесплатном Render диск **временный** —
> после деплоя или «засыпания» сервиса аккаунты пропадут. Перед реальным запуском кабинета
> нужен постоянный диск или БД (см. «Деплой»).

## Запуск локально

Нужен только [Node.js 22+](https://nodejs.org/) (проверить: `node --version`).

```bash
git clone https://github.com/SAKEDA-hub/neptun-aquapark-site.git
cd neptun-aquapark-site
npm start                 # сайт + API на http://localhost:3000
```

- Сайт: http://localhost:3000
- Данные страницы: http://localhost:3000/api/site
- Личный кабинет: http://localhost:3000/account (демо-аккаунты включаются `DEMO_ACCOUNTS=1`)
- Админка отзывов и заказов: http://localhost:3000/admin — нужна переменная `ADMIN_TOKEN` (ниже)

Настройки — в `backend/.env` (скопируйте `backend/.env.example`), например:

```bash
cp backend/.env.example backend/.env
# впишите ADMIN_TOKEN=любая-длинная-строка
npm run dev               # то же, что start, но перезапускается при изменении файлов
```

Отзывы сохраняются в `backend/data/feedback.jsonl`, аккаунты и сессии — `accounts.json`,
заказы магазина — `orders.json`, записи на занятия — `bookings.json` (одна строка/объект
в JSON, папка в `.gitignore`).

Только фронтенд, без бэкенда: `cd frontend && npm run dev` (python, порт 8080) — страница возьмёт
встроенные данные, форма отзыва покажет телефон.

## Тесты

```bash
npm test                  # фронтенд + бэкенд, Node.js ≥ 22
```

Бэкенд: все эндпоинты, ETag/304, honeypot, rate limit, коды 400/401/403/404/405/409/413/415/422/429/503,
защита от path traversal, валидация, разбор IP за прокси. Магазин: валидация карт по Луне,
тестовые сценарии шлюза (успех → абонемент, отклонение, недостаточно средств), идемпотентность
заказов (повтор не создаёт второго и не списывает дважды), подпись и проверка чека, лимиты попыток,
repair-логика «оплачено, но абонемент не выдан» при падении сервера. Расписание: окно 14 дней,
доступ по категории абонемента, дедлайн записи за час, повторная запись того же слота (200),
отмена до дедлайна.

Фронтенд: чистые функции (расписание и статус «открыто/закрыто», расчёт стоимости и выгоды
абонементов, форматирование, склонения, экранирование HTML, фильтр горок по росту, валидация отзыва)
и целостность данных в `site-data.js` — она же защита от опечаток в будущем ответе API.

## Деплой на бесплатный хостинг (Render)

В репозитории есть `render.yaml` — Render создаст сервис сам.

1. Зайдите на [render.com](https://render.com) через GitHub (бесплатно, карта не нужна).
2. Откройте https://render.com/deploy?repo=https://github.com/SAKEDA-hub/neptun-aquapark-site
   (репозиторий приватный — Render попросит доступ к нему, разрешите).
3. Нажмите **Deploy Blueprint**. Через 1–2 минуты сайт будет на `https://neptun-aquapark.onrender.com`
   (или похожем адресе — он виден в Dashboard).
4. Токен админки: Dashboard → сервис → **Environment** → `ADMIN_TOKEN` (сгенерирован автоматически).
5. Каждый push в `main` выкатывается автоматически.

Особенности бесплатного тарифа Render:

- сервис «засыпает» после 15 минут без посещений, первое открытие после этого — около минуты;
- **диск не сохраняется** между перезапусками: `feedback.jsonl` и `accounts.json` (аккаунты клиентов!)
  пропадают при каждом деплое/засыпании.
  Поэтому на free-тарифе настройте Telegram (ниже) — уведомление и будет постоянной копией отзыва.
  Для постоянного хранения: платный тариф с Disk (`DATA_DIR=/var/data`) или своя БД.

Другие хостинги: `Dockerfile` в корне (Koyeb, Fly.io, любой VPS):

```bash
docker build -t neptun .
docker run -p 3000:3000 -e ADMIN_TOKEN=... -v neptun-data:/data neptun
```

На VPS без Docker: `npm start` под systemd/pm2 за nginx с `TRUST_PROXY=1`.

## Уведомления в Telegram

1. В Telegram напишите [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен бота.
2. Напишите своему боту любое сообщение (или добавьте его в рабочую группу).
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — в ответе `"chat":{"id": …}` это `TELEGRAM_CHAT_ID`.
4. Задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (в `backend/.env` или в Environment на Render).

## Настройки (переменные окружения)

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `3000` | порт (Render задаёт сам) |
| `ADMIN_TOKEN` | — | пароль для `/admin`; без него админка выключена |
| `PAYMENT_SECRET` | случайный при запуске | HMAC-ключ подписи чеков магазина; задайте постоянный — иначе подписи «протухнут» после перезапуска |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | — | уведомления о новых отзывах |
| `DATA_DIR` | `backend/data` | где хранить `feedback.jsonl`, `accounts.json`, `orders.json`, `bookings.json`, `audit.jsonl` |
| `TRUST_PROXY` | `0` | число прокси перед сервером (Render, nginx — `1`) |
| `DEMO_ACCOUNTS` | пусто | `1` — создавать демо-аккаунты кабинета при запуске |
| `FEEDBACK_RATE_MAX`, `FEEDBACK_RATE_WINDOW_MIN` | `5`, `10` | не больше N отзывов с IP за M минут |

## Бэкенд: как устроен

- `GET /api/site` отдаёт `frontend/assets/js/config/site-data.js` — **один источник данных** для сайта и API,
  с ETag и кешем 5 минут. Фронтенд берёт данные из API, а если он недоступен — из встроенной копии.
- `POST /api/feedback` — валидация (те же правила, что в форме, + типы и длины), honeypot, rate limit,
  запись в файл, уведомление в Telegram. Ответы — по [`docs/api-contract.md`](docs/api-contract.md).
- `GET /api/admin/feedback` — список отзывов, `Authorization: Bearer <ADMIN_TOKEN>`; страница `/admin` поверх него
  (поиск, экспорт в CSV для Excel).
- Безопасность: CSP и другие заголовки, лимит тела 16 КБ, наружу отдаются только `index.html` и `assets/`,
  сравнение токена за постоянное время, отдельный лимит на неверный токен.
- Хранилище отзывов спрятано за интерфейсом `{ add, list }` (`store.js`) — переход на SQLite/Postgres
  не затронет остальной код.
- Личный кабинет (`accounts.js`):
  - пароли — `scrypt` с уникальной солью; в файле нет ни паролей, ни токенов сессий (только SHA-256);
  - сессия — cookie `neptun_sid`: `HttpOnly`, `SameSite=Lax`, `Secure` за HTTPS (`TRUST_PROXY=1`), 30 дней;
  - CSRF: проверка `Origin` + обязательный `Content-Type: application/json`;
  - перебор: не больше 8 неверных паролей на почту и 20 на IP за 15 минут, 10 регистраций с IP в час;
    на «нет такой почты» и «неверный пароль» — одинаковый ответ и время ответа;
  - смена пароля завершает сеансы на других устройствах;
  - правила полей общие для формы и сервера: `frontend/assets/js/utils/account.js`;
  - тарифы абонементов строятся из `site-data.js` — новые цены сразу появляются в админке.
  - Восстановления пароля по почте нет (нужен SMTP) — пока через ресепшен; администратор может удалить
    аккаунт вручную в `accounts.json`, клиент зарегистрируется заново.
- Магазин (`payments.js`):
  - цена заказа — только из каталога на сервере; тело запроса цену не содержит (подменить нечем);
  - `Idempotency-Key` обязателен (16–80 символов): двойной клик не создаёт второй заказ;
  - переход `pending → paid` — атомарная мутация стора: параллельные попытки выигрывает одна,
    повторная отправка возвращает `alreadyPaid: true` без нового списания;
  - карта валидируется (Луна, срок, CVC, держатель) и не хранится — в файлах и журнале только
    последние 4 цифры; проверка карт — общий модуль фронта и бэка `utils/card.js`;
  - чек подписывается HMAC-SHA256 (`PAYMENT_SECRET`), проверка — `timingSafeEqual`;
  - чужой заказ и несуществующий возвращают одинаковый `404`;
  - лимиты: создание 20/ч (пользователь) и 40/ч (IP), оплата 30/15 мин (из них неудачных 10);
    неоплаченный заказ живёт 24 часа, потом `expired`;
  - если сервер упал между оплатой и выдачей абонемента, `GET /api/orders/:id` доделывает выдачу;
  - аудит — append-only журнал `data/audit.jsonl` без данных карты.
- Расписание (`bookings.js` + `schedule.js`): окно 14 дней, слоты из `site-data.js → schedule`,
  доступ по категории абонемента (`pool` → бассейн и аквааэробика, `fitness` — всё), запись не позднее
  чем за час до старта, не больше 15 будущих записей, повторная запись того же слота идемпотентна.

## Как обновлять данные сейчас

Всё содержимое — цены аквапарка и бассейна, клубные карты, команда тренеров, прайс массажа,
солярия и прессотерапии, часы работы, горки — в `frontend/assets/js/config/site-data.js`.
Переводы на казахский — в `frontend/assets/js/config/i18n.js`.
После правки — push в `main`: сайт и `/api/site` обновятся вместе.

## Соглашения

- CSS: токены только в `tokens.css`; новая секция → новый файл в `sections/` + строка в `main.css`.
- JS: модуль экспортирует `init*`/`render*` и не обращается к глобальному состоянию;
  логика без DOM — в `utils/` и покрывается тестами.
- Всё, что подставляется в `innerHTML` из данных, проходит через `escapeHtml`.
- Отступы 2 пробела, LF, UTF-8 (`.editorconfig`).
